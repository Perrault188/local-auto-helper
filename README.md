# Local Auto Helper

一个本地优先的自动帮办演示项目。它展示如何把自然语言需求整理成受约束的工作流，并在本机用Mock适配器完成任务创建、定时触发、文件收取、改名、登记、提醒和运行记录展示。

项目只提供本地演示能力。它没有连接真实即时通讯、网盘或通知服务，也不应直接暴露到公网。

## 主要能力

- 用对话或表单创建自动帮办
- 支持发布、收取和提醒三类受控能力
- 用SQLite保存任务、运行记录和演示文件
- 用Mock适配器模拟消息和文件动作
- 默认使用本地规则识别意图
- 可选接入DashScope兼容接口，只用于受约束的意图分类
- 提供契约、合成fixture和Node测试

## 环境要求

- Node.js 24或更高版本
- npm

## 本地运行

```bash
npm install
npm test
npm start
```

然后打开`http://127.0.0.1:4173`。

服务固定监听本机回环地址。默认数据保存在`demo/local-data`，该目录已加入忽略清单。设置`AUTO_HELPER_DATA_DIR`可以改用其他本地目录。

## 可选模型配置

不设置模型密钥时，应用自动使用本地规则识别。需要启用远程意图分类时，复制`.env.example`中的变量到自己的未跟踪环境文件或终端环境。不要提交真实密钥。

远程模型只返回受约束的意图候选。工作流能力、参数校验和执行仍由本地确定性代码控制。

## 项目结构

```text
contracts/   JSON Schema和接口契约
demo/        本地HTTP服务
docs/        公开架构、隐私和发布说明
engine/      工作流领域逻辑、执行器和存储
fixtures/    合成演示与评估数据
prototype/   无构建步骤的前端界面
tests/       单元、接口、契约和安全回归测试
```

## 数据和隐私

仓库内的姓名、用户ID、群组、消息和文件路径均为合成示例。运行后产生的SQLite文件、日志、下载文件和本地环境变量不会被Git跟踪。更完整的边界见[PRIVACY.md](PRIVACY.md)。

## 安全边界

- 只在可信本机运行
- 不要反向代理到公网
- 不要把真实业务数据用于演示fixture
- 不要在仓库、截图、Issue或日志中提交密钥
- 远程模型配置属于可选能力，默认关闭

安全说明和问题报告方式见[SECURITY.md](SECURITY.md)。
